观察日期：2026-10-02。Star 数来自当天 GitHub API，只是关注度快照；不作为质量评分或因果证据。
以下做法是对公开 README、示例、文档和工程入口的观察与本项目的取舍。

| 项目 | 当日 Star | 可观察的做法 | 本项目采用的做法 |
| --- | ---: | --- | --- |
| [LlamaFactory](https://github.com/hiyouga/LlamaFactory) | 75,266 | 明确微调用途、快速上手、界面演示、支持矩阵、文档与论文引用入口 | 中英文入口、实际报告截图、清晰格式范围、具体接入示例、软件引用信息 |
| [DeepSpeed](https://github.com/deepspeedai/DeepSpeed) | 43,172 | 性能与规模是核心价值，提供配置／教程／CI／研究论文等证据入口 | 明确指标和环境，保存原始测量，区分工程验证与研究结论 |
| [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) | 241,954 | 清楚标注 developer preview、简洁运行路径、插件定位和贡献入口 | 标注成熟度、保持快速上手短小、模块分工清楚、贡献需求具体 |

这是借鉴项目表达和工程结构，不是复制其设计资产、性能数字、用户案例或研究贡献。
它们的团队、品牌、发布时机与生态背景不同，模仿 README 不能保证获得相同传播结果。

## 本次落地的结构

1. **第一页解释价值：** 谁使用、在训练流程哪个位置使用、预期产出是什么。
2. **一分钟验证：** 安装、运行现成样例、打开真实 HTML 报告。
3. **先给证据，再讲愿景：** 合成故障回归、CPU 测量、固定版本上游示例；分别说明不能推导什么。
4. **图片可追溯：** 报告截图由运行结果生成，基准图由保存的 JSON 生成；保留生成脚本。
5. **边界和接入明确：** 不支持格式、schema 版本、退出码、数据不修改、训练仍需验证。
6. **科学与落地说明分开：** 写清现在能支持的工作，以及需要真实数据／GPU 实验才能成立的结论。
7. **持续维护入口：** CI、变更日志、问题模板、贡献指南与可验证的下一步目标。

## 仍需长期积累的部分

- 有真实外部使用者，而不只是作者自测。
- 有真实问题驱动的规则与兼容性扩展，并记录误报和漏检。
- 有独立复现和公开的上游协作记录。
- 有数据驱动的性能改进，而不只是增加功能和扩大 README。

这些积累没有通过本次改版自动完成，也不应伪造成“已被业界广泛使用”。
